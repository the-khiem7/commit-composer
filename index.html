Cut at the hunk, not the file

Real work is tangled: one file holds a bug fix and half a feature. commit-composer splits the working tree into hunks, groups them by project, action and target, and gives every group its own Conventional Commits message.

No git add -p sessions, no file-sized compromises. A unit is named by a hash of its file and content, not its line number, so the name survives every commit before it.

It always stops at the plan

Every run takes a snapshot first, lists the hunks, names the project, groups them, prints the plan and then stops. Nothing is staged or committed until you approve the grouping.

  • regroup
  • rename
  • drop any group

The title is always type(project): subject.

Two signals before every commit

scan reads the staged diff for keys and credentials and names the file and the rule, never the value. lint checks the message against the format. Either one prints FAIL, and that commit does not happen. Both print an OK line on a pass.

Both gates read patterns. They are a floor, not a verdict: a secret without a rule passes them.

End of the line

Some moves are not on the map. Every run ends with the starting tree id and HEAD id: one restores the index, the other removes the new commits and keeps every change in the working tree.

  • no pushyours to run
  • no amendno rebase, tag or branch
  • no early commitnot before you approve the plan
  • no commit on FAILfrom scan or lint
